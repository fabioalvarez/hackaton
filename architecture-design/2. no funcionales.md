# Requisitos no funcionales — Nodo Ruta

Los requisitos no funcionales se dividen en dos tipos, que se verifican de forma distinta:

| | Atributo de calidad | Constraint (restricción) |
|---|---|---|
| Naturaleza | Propiedad con grados (más o menos) | Condición fija: se cumple o no |
| Se verifica con | Escenario (fuente, estímulo, ambiente, artefacto, respuesta, medida de respuesta) | Lista de verificación |

> Los valores numéricos de las medidas de respuesta son **propuestas** para el prototipo. Hay que validarlos con el equipo.

---

## 1. Atributos de calidad seleccionados

| Atributo | Por qué (origen en el reto) | Prioridad |
|---|---|---|
| **Availability & Resilience** | Hoy, si la instancia cae, el servicio deja de responder. Se debe probar la detención de una instancia. | Alta |
| **Recoverability** | No hay procedimiento probado para recuperar datos ni versión funcional, ni se sabe cuánto tarda. | Alta |
| **Durability** | Los datos se guardan junto a la aplicación y se pierden con el contenedor. | Alta |
| **Deployability** | La configuración se aplica manualmente. | Media |
| **Observability** | Se pide comprobar salud, consultar registros y saber qué instancia atendió. | Media |
| **Cost Efficiency** | No se puede contratar nada de pago; hay que identificar los factores de consumo que generan costo y retirar los recursos de prueba. | Alta |

**Descartados (el reto no los pide):** elasticidad, escalabilidad, aislamiento multiusuario y rendimiento. No se simula tráfico real.

---

## 2. Escenarios de calidad

### QA-01 · Availability & Resilience

| Elemento | Descripción |
|---|---|
| Fuente | Falla de infraestructura |
| Estímulo | Una de las dos instancias del servicio se detiene |
| Ambiente | Operación normal, con consultas en curso |
| Artefacto | Servicio de consulta (punto de acceso común + instancias) |
| Respuesta | Las solicitudes se atienden con la instancia restante, sin intervención manual |
| Medida de respuesta | ≥ 99 % de las solicitudes exitosas durante la prueba; máximo 10 s hasta que el punto de acceso deja de enviar solicitudes a la instancia caída |

### QA-02 · Recoverability (datos)

| Elemento | Descripción |
|---|---|
| Fuente | Responsable técnico (o error operativo) |
| Estímulo | Los datos del servicio se pierden o se modifican |
| Ambiente | Servicio en operación, con un respaldo existente fuera de la copia de trabajo |
| Artefacto | Almacén de datos y procedimiento de respaldo/restauración |
| Respuesta | Se restauran los datos desde el respaldo y se verifica la restauración |
| Medida de respuesta | Tiempo de recuperación ≤ 5 min; el identificador de versión y el contenido coinciden al 100 % con el respaldo |

### QA-03 · Durability

| Elemento | Descripción |
|---|---|
| Fuente | Responsable técnico |
| Estímulo | Se actualiza o recrea un contenedor del servicio |
| Ambiente | Operación normal |
| Artefacto | Almacenamiento de datos y contenedores |
| Respuesta | El servicio inicia con los datos previos |
| Medida de respuesta | 0 pedidos perdidos o modificados; misma versión de datos antes y después |

### QA-04 · Recoverability (versión)

| Elemento | Descripción |
|---|---|
| Fuente | Responsable técnico |
| Estímulo | Se publica una versión con un error que deja de responder las consultas |
| Ambiente | Operación normal |
| Artefacto | Imagen del servicio y despliegue |
| Respuesta | Se vuelve a la última versión funcional conservando los datos |
| Medida de respuesta | Servicio restablecido en ≤ 5 min; 0 pedidos perdidos |

### QA-05 · Deployability

| Elemento | Descripción |
|---|---|
| Fuente | Responsable técnico |
| Estímulo | Necesita recrear el despliegue completo en un entorno limpio |
| Ambiente | Equipo sin configuración previa, solo con los archivos o instrucciones del repositorio |
| Artefacto | Archivos de despliegue y configuración |
| Respuesta | El servicio queda operativo con las dos instancias y el punto de acceso común |
| Medida de respuesta | ≤ 10 min; 0 pasos de configuración manual fuera de las instrucciones |

### QA-06 · Observability

| Elemento | Descripción |
|---|---|
| Fuente | Responsable técnico |
| Estímulo | Debe diagnosticar un incidente (por ejemplo, una instancia detenida) |
| Ambiente | Operación con dos instancias |
| Artefacto | Salud y registros del servicio |
| Respuesta | Identifica qué instancia falló y cuál atendió cada solicitud |
| Medida de respuesta | Diagnóstico en ≤ 2 min; 100 % de las solicitudes de la prueba trazables a una instancia |

### QA-07 · Cost Efficiency

| Elemento | Descripción |
|---|---|
| Fuente | Equipo (responsable técnico) |
| Estímulo | Mantiene el entorno de prueba desplegado durante la hackatón y luego lo cierra |
| Ambiente | Cuenta educativa o sin cobros; uso solo de prueba |
| Artefacto | Entorno desplegado (instancias, almacenamiento y respaldos) |
| Respuesta | El consumo se mantiene dentro de lo gratuito y, al terminar, se retiran los recursos de prueba |
| Medida de respuesta | Gasto total = 0; 0 recursos activos ≤ 15 min después de cerrar las pruebas; factores de consumo identificados para el 100 % de los componentes |

## 3. Constraints seleccionados

Cada constraint se verifica con una lista de comprobación, no con un escenario.

| ID | Condición | Verificación | Si se viola |
|---|---|---|---|
| CT-01 | No hay secretos dentro de la imagen ni claves publicadas en repositorios. | Revisar imagen y repositorio | Exposición de credenciales |
| CT-02 | La exposición de red se limita a lo necesario para la demostración. | Revisar puertos publicados | Superficie de ataque innecesaria |
