# Diseño arquitectónico — Nodo Ruta

## 1. Estilo arquitectónico

**Service-Based (servicio único replicado) + Client-Server**

- Un solo servicio de consulta, sin dominios que separar.
- Se replica en 2 instancias sin estado, detrás de un punto de entrada común, con los datos en un almacenamiento persistente compartido.
- Microservicios, event-driven y serverless se descartan: no hay varias capacidades ni cargas variables que lo justifiquen.

```
Cliente ──► Balanceador ──┬─► Instancia A ──┐
          (health checks) └─► Instancia B ──┴─► Almacenamiento persistente ──► Respaldo
```

## 2. Patrones y tácticas (uno por escenario)

| Escenario | Táctica / patrón | Cómo se aplica |
|---|---|---|
| QA-01 Availability & Resilience | **Redundancia activa** (táctica) | 2 instancias detrás de un balanceador que comprueba su salud y deja de enviar solicitudes a la que falla. |
| QA-02 Recoverability (datos) | **Backup & Restore** (táctica) | Copia del archivo de datos a un almacenamiento separado, con la versión en el nombre; restauración que compara versión y contenido. |
| QA-03 Durability | **Externalized State** (patrón) | Los datos viven en un almacenamiento persistente fuera de las instancias. |
| QA-04 Recoverability (versión) | **Rollback automático** (táctica) | Versiones de imagen fijas; si la nueva falla la comprobación de salud, el despliegue vuelve solo a la anterior. Los datos no se tocan. |
| QA-05 Deployability | **Infraestructura como código** (patrón) | Todo el entorno se define en archivos versionados y se crea o destruye con un solo comando. |
| QA-06 Observability | **Monitor / Logging** (táctica) | Registros con el ID de instancia en cada línea y en cada respuesta. |

**Constraints:** CT-01 se cumple manteniendo las credenciales fuera de la imagen y del repositorio. CT-02 se cumple exponiendo hacia el exterior solo el punto de entrada.

## 3. Lógica

- **Síncronas:** Cliente → Balanceador → Instancia → Almacenamiento. Es una consulta que espera respuesta.
- **Asíncronas:** ninguna. No hay procesos en segundo plano ni mensajería.
- **Respaldo y restauración:** procedimiento definido y repetible, fuera del flujo de consulta.
- Sin procesos de varios pasos, por lo que no hay coreografía ni orquestación.

## 4. Persistencia

### Requerimientos

| # | Requerimiento | Origen |
|---|---|---|
| P1 | Los datos sobreviven a la caída o recreación de una instancia | QA-03, reto |
| P2 | Los datos están separados de la aplicación | Reto |
| P3 | Las 2 instancias leen la misma fuente | QA-01 |
| P4 | Existe un respaldo fuera de la copia de trabajo | QA-02, reto |
| P5 | Se puede restaurar y comparar versión y contenido | QA-02, reto |
| P6 | Datos pequeños (6 pedidos y su versión), solo lectura | Reto |
| P7 | Cambio mínimo de código y despliegue simple | Reto, QA-05 |
| P8 | No se exige base de datos distribuida | Reto |

### Opciones evaluadas

| Opción | P1 a P3 | P4 y P5 | P7 (simplicidad, cambio de código) |
|---|---|---|---|
| **A. Archivo en almacenamiento persistente compartido** | Cumple | Cumple (copiar el archivo) | Mejor: sin cambios de código |
| B. Base de datos relacional | Cumple | Cumple (volcado) | Cambio medio y un componente más |
| C. Base de datos documental | Cumple | Cumple (volcado) | Cambio bajo y un componente más |
| D. Almacenamiento de objetos | Cumple | Cumple (versionado) | Cambio bajo |

### Selección: A

Todas cumplen los requerimientos. A es la más simple, no cambia el código y coincide con lo que describe el reto: respaldar el archivo de datos, alterar una copia y restaurarla.

- **Almacén:** el archivo de datos (pedidos y versión) vive en un almacenamiento persistente fuera de las instancias.
- **Acceso:** ambas instancias lo leen; solo lectura, por lo que no hay escrituras concurrentes.
- **Respaldo:** copia del archivo a un almacenamiento distinto, con la versión en el nombre, antes de cada cambio de versión de los datos.
- **Restauración:** se copia el respaldo de vuelta y se compara la versión y el contenido.
- **Consistencia:** no aplica entre servicios; hay una sola fuente de datos.
