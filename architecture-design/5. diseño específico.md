### 1.1 Stack

| Decisión | Valor |
|---|---|
| Lenguaje | Python 3.12 |
| Framework | FastAPI (servidor ASGI: uvicorn) |
| Gestión de paquetes | `uv` (`pyproject.toml` + `uv.lock` versionado; `uv sync --frozen` en la imagen) |
| Estado | Stateless: sin caché ni variables globales mutables; cada solicitud lee el archivo de datos |

### 1.2 Contrato (A1–A4)

Solo `GET`. Cualquier otro método responde `405`; cualquier otra ruta, `404`. Todas las respuestas son JSON UTF-8 e incluyen `instancia` (A4) y el header `X-Instance-Id`.

| Operación | Ruta | 200 | Error | Req. |
|---|---|---|---|---|
| Inicio | `GET /` | `{"servicio": "Nodo Ruta", "instancia": "...", "rutas": ["/health", "/pedidos"]}` | — | RF-03 |
| Salud | `GET /health` | `{"estado": "ok", "instancia": "...", "version_datos": "datos-v1"}` | `503 {"estado": "error_datos", "instancia": "..."}` | RF-04 |
| Pedidos | `GET /pedidos` | `{"instancia": "...", "version": "datos-v1", "pedidos": [{"id", "zona", "estado"}, ...]}` | `503 {"estado": "error_datos", "instancia": "..."}` | RF-01, RF-02 |
| No encontrada | cualquier otra | — | `404 {"error": "Ruta no disponible", "instancia": "..."}` | RF-05 |

- Sin parámetros de entrada ni paginación (6 pedidos; el reto no pide filtros).
- `/pedidos` devuelve los pedidos tal como están en el archivo, sin transformarlos (el contenido debe coincidir al 100 % con el respaldo, QA-02/QA-03).
- Se desactivan `/docs`, `/redoc` y `/openapi.json` (CT-02: superficie mínima). Se reemplazan por `404` con el mismo formato.

### 1.3 Lectura de datos (A5)

- Ruta del archivo: variable `DATA_PATH` (en ECS, el punto de montaje de EFS, solo lectura).
- Se lee y valida **en cada solicitud** a `/pedidos` y `/health`. Así una versión nueva cargada en EFS se ve en ambas tareas sin reiniciarlas, y no hay estado local que perder.
- Validación: JSON válido, objeto con `version` (string no vacío) y `pedidos` (lista). Si falla (archivo ausente, ilegible o inválido) → `503 error_datos`.
- La lectura se hace con una función síncrona simple (`def`, no `async def`) para que FastAPI la ejecute en su threadpool sin bloquear el loop.

### 1.4 Identificación de la instancia (A4)

- `INSTANCE_ID` viene del entorno. En ECS se inyecta el ID de la tarea; si no está definida, se usa `socket.gethostname()` (en Fargate es único por tarea).
- Un middleware añade `X-Instance-Id` a **toda** respuesta, incluidos los 404, 405 y 503. El campo `instancia` del cuerpo se arma con el mismo valor.

### 1.5 Salud (A3, A9)

- `/health` solo responde `ok` si **puede leer y validar los datos**, no solo si el proceso vive. Es la misma ruta que usa el health check del ALB y del circuit breaker de ECS.
- Una versión defectuosa (A9) debe fallar este chequeo (p. ej. no arranca o devuelve 503), de modo que ECS no la marque sana y revierta. Cómo se provoca la falla en la prueba se define en la sección 5.
- Sin dependencias externas en el chequeo: solo el archivo de datos.

### 1.6 Registro de solicitudes (A6)

- Un middleware escribe **una línea JSON por solicitud** a stdout (lo recoge `awslogs` hacia CloudWatch).
- Campos: `ts` (ISO 8601 UTC), `instancia`, `metodo`, `ruta`, `status`, `ms`, `version_datos` (si se leyó).
- Los logs de uvicorn se redirigen al mismo formato JSON. El detalle de consultas y el formato final se cierran en la sección 7.

### 1.7 Configuración (A7, CT-01)

Todo por variables de entorno; ninguna con secreto.

| Variable | Defecto | Uso |
|---|---|---|
| `DATA_PATH` | `/data/pedidos.json` | Archivo de datos (montaje EFS) |
| `INSTANCE_ID` | hostname | Identificador de la instancia |
| `PORT` | `8080` | Puerto de escucha |
| `LOG_LEVEL` | `info` | Nivel de log |

- Se lee con `pydantic-settings` en una sola clase `Settings`. Si una variable tiene un valor inválido, el proceso falla al arrancar (falla rápida, visible en el rollback).
- La imagen **no** incluye `pedidos.json` (distinto del Dockerfile original): los datos viven en EFS (QA-03).

### 1.8 Imagen (A8)

- Base fija por versión: `python:3.12-slim` (se fija el digest al publicar).
- `uv` se copia desde la imagen oficial `ghcr.io/astral-sh/uv` en una etapa de build; la imagen final solo lleva el `.venv` y el código.
- Multi-stage, usuario no root (`10001`), `EXPOSE 8080`, `CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8080"]`.
- Etiqueta inmutable por versión (`nodo-ruta:1.0.0`, nunca `latest`) para poder volver a la última versión funcional (QA-04).
