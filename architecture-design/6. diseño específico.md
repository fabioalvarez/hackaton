### 1.1 Stack

| Decisión | Valor |
|---|---|
| Lenguaje | Python 3.12 |
| Framework | FastAPI (servidor ASGI: uvicorn) |
| Gestión de paquetes | `uv` (`pyproject.toml` + `uv.lock` versionado; `uv sync --frozen` en la imagen) |
| Estado | Stateless: sin caché ni variables globales mutables; cada solicitud lee el archivo de datos |

### 1.2 Contrato (A1–A4)

Solo `GET`. Cualquier otro método responde `405`; cualquier otra ruta, `404`. Todas las respuestas son JSON UTF-8 e incluyen el header `X-Instance-Id` (A4), que es el único lugar donde se informa la instancia; el cuerpo no la repite. Todo el contrato (rutas, campos, valores y mensajes de error) está en inglés.

| Operación | Ruta | Respuestas | Req. |
|---|---|---|---|
| Inicio | `GET /` | 200 | RF-03 |
| Salud | `GET /health` | 200, 503 | RF-04 |
| Pedidos | `GET /orders` | 200, 503 | RF-01, RF-02 |
| Cualquier otra ruta | — | 404 | RF-05 |

**`GET /`** → `200`

`service` toma su valor de `SERVICE_NAME`; `routes` se arma a partir de las rutas registradas (no es una lista fija).

```json
{
  "service": "Next",
  "routes": ["/health", "/orders"]
}
```

**`GET /health`** → `200`

```json
{
  "status": "ok",
  "data_version": "data-v1"
}
```

**`GET /orders`** → `200`

```json
{
  "data_version": "data-v1",
  "orders": [
    { "id": "ORD-001", "zone": "North", "status": "in_transit" },
    { "id": "ORD-002", "zone": "Center", "status": "delivered" }
  ]
}
```

**`/health` o `/orders` con datos ilegibles o inválidos** → `503`

```json
{
  "status": "data_error"
}
```

**Ruta inexistente** → `404`

```json
{
  "error": "Route not found"
}
```

| Aspecto | Definición |
|---|---|
| Valores de `status` de un pedido | `pending`, `preparing`, `in_transit`, `delivered` |
| Parámetros de entrada | Ninguno; sin paginación (6 pedidos, el reto no pide filtros) |
| Contenido de `/orders` | Los pedidos tal como están en el archivo, sin transformarlos (debe coincidir al 100 % con el respaldo, QA-02/QA-03). Por eso el archivo usa los mismos nombres de campo en inglés (sección 2) |
| `/docs`, `/redoc`, `/openapi.json` | Desactivadas (CT-02: superficie mínima); responden `404` con el mismo formato |

### 1.3 Lectura de datos (A5)

| Aspecto | Definición |
|---|---|
| Ruta del archivo | Variable `DATA_PATH`. En el despliegue (tareas de ECS Fargate) apunta a la carpeta donde se monta EFS en el contenedor, en solo lectura; en local, a un archivo cualquiera |
| Cuándo se lee | En **cada solicitud** a `/orders` y `/health`. Una versión nueva cargada en EFS se ve en ambas tareas sin reiniciarlas, y no hay estado local que perder |
| Validación | JSON válido; objeto con `data_version` (string no vacío) y `orders` (lista) |
| Si la validación falla | Archivo ausente, ilegible o inválido → `503 data_error` |
| Implementación | Función síncrona (`def`, no `async def`): FastAPI la ejecuta en su threadpool sin bloquear el loop |

### 1.4 Identificación de la instancia (A4)

| Aspecto | Definición |
|---|---|
| Origen del ID | Variable `INSTANCE_ID`, que el despliegue inyecta con el ID de la tarea |
| Si no está definida | `socket.gethostname()` (en Fargate es único por tarea) |
| Dónde aparece | Solo en el header `X-Instance-Id`, en **toda** respuesta (también 404, 405 y 503). El cuerpo no lleva el campo |
| Cómo se añade | Un middleware |

### 1.5 Salud (A3, A9)

| Aspecto | Definición |
|---|---|
| Cuándo responde `ok` | Solo si **puede leer y validar los datos**, no solo si el proceso vive |
| Quién la consulta | Health check del ALB y circuit breaker de ECS (la misma ruta) |
| Versión defectuosa (A9) | Debe fallar este chequeo (no arranca o devuelve 503) para que ECS no la marque sana y revierta. Cómo se provoca en la prueba: sección 5 |
| Dependencias | Ninguna externa; solo el archivo de datos |

### 1.6 Registro de solicitudes (A6)

| Aspecto | Definición |
|---|---|
| Formato | Una línea JSON por solicitud, escrita por un middleware |
| Destino | stdout; lo recoge `awslogs` hacia CloudWatch |
| Campos | `ts` (ISO 8601 UTC), `instance` (mismo valor del header), `method`, `path`, `status`, `ms`, `data_version` (si se leyó) |
| Logs de uvicorn | Se redirigen al mismo formato JSON |
| Pendiente | Consultas y formato final: sección 7 |

### 1.7 Configuración (A7, CT-01)

Todo por variables de entorno; ninguna con secreto.

| Variable | Defecto | Uso |
|---|---|---|
| `DATA_PATH` | `/data/orders.json` | Archivo de datos (montaje EFS) |
| `INSTANCE_ID` | hostname | Identificador de la instancia |
| `SERVICE_NAME` | `Next` | Nombre del servicio que muestra `GET /` |
| `PORT` | `8080` | Puerto de escucha |
| `LOG_LEVEL` | `info` | Nivel de log |

| Aspecto | Definición |
|---|---|
| Lectura | `pydantic-settings`, en una sola clase `Settings` |
| Valor inválido | El proceso falla al arrancar (falla rápida, visible en el rollback) |
| Datos en la imagen | La imagen **no** incluye `orders.json` (distinto del Dockerfile original); los datos viven en EFS (QA-03) |

### 1.8 Imagen (A8)

| Aspecto | Definición |
|---|---|
| Base | `python:3.12-slim` (se fija el digest al publicar) |
| Construcción | Multi-stage; `uv` se copia desde `ghcr.io/astral-sh/uv` en la etapa de build; la imagen final solo lleva el `.venv` y el código |
| Usuario / puerto | No root (`10001`); `EXPOSE 8080` |
| Comando | `next` (script que arranca uvicorn con `PORT`) |
| Etiqueta | Inmutable por versión (`next:1.0.0`, nunca `latest`), para volver a la última versión funcional (QA-04) |

### 1.9 Estructura del código

```
api/
├── pyproject.toml     # dependencias (uv)
├── uv.lock            # versiones bloqueadas
├── Dockerfile         # imagen
├── src/
│   └── next/
│       ├── main.py           # create_app(): arma la app (middlewares, repositorio, rutas)
│       ├── routes.py         # endpoints y handlers de 404/405/503
│       ├── settings.py       # Settings (variables de entorno)
│       ├── data.py           # modelos y OrderRepository (lectura y validación)
│       ├── observability.py  # logs JSON, header X-Instance-Id, log por solicitud
│       └── utils.py          # funciones auxiliares (list_route_paths)
└── tests/             # pytest + TestClient (casos de RF-01 a RF-05)
```
